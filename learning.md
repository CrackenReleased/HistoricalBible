# Testing lessons

## 2026-10-20 23:28:18 — An artifact URL is not a claim review (v00.01.57)

For archaeology cards, anchor each public claim to an object or inscription edition ID and record exactly what it says, how it is dated, why it is connected to a passage, and what it does not establish. An apparently relevant museum link can target a different object; similarly, an artifact can be placed at the wrong city or linked to the wrong biblical person. A receipt with a `proposed` or `disputed` connection keeps the artifact discoverable without promoting a tentative identity to fact. Preserve separate text and image rights even when a source is publicly viewable.

## 2026-10-18 16:24:30 — Test discovery is part of coverage (v00.01.55)

A green default command can omit entire runtimes. Inventory actual test files against every runner before claiming full-suite success. Keep fast repository-only tests in the default command and give local-artifact acceptance an explicit full-suite entry point with documented dependencies; fail visibly rather than silently skip missing artifacts. A test's filename or historic version is not evidence it is obsolete. Replace implementation-string/duplicated-algorithm checks with observable behavior, and preserve canonical proof fixtures and feature assertions.
